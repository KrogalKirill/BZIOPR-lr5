# Поддержка принятия решений на основе метода Монте-Карло (GUI, Python)

Лабораторная работа №5 по курсу «Базы знаний и поддержка принятия решений».  
Проект реализует систему поддержки принятия решений для производственно-экономической задачи на основе имитационного моделирования методом Монте-Карло с псевдослучайными числами, генерируемыми сдвиговым регистром с линейной обратной связью (LFSR).

---

## 1. Постановка задачи (Вариант 6)

На предприятие поступает партия комплектующих изделий (резисторов) невысокой точности (N = 10\,000 шт.).  
Требуется определить долю деталей ($P \in [0, 1]$ с шагом 5%), подвергаемых предварительному входному контролю, при которой суммарные издержки предприятия будут минимальными.

### Исходные параметры:
* **A (доля бракованных резисторов):** $15\%$ ($p_{\text{def}} = 0.15$)
* **$B$ (стоимость входного контроля одного резистора):** $7$ руб.
* **$C$ (стоимость подгонки при выявлении брака на контроле):** $50$ руб.
* **$D$ (стоимость замены бракованного резистора в готовом блоке):** $125$ руб.
* **Генератор ПСЧ:** LFSR степени 32 по **полиному №15**:
  $$X^{32} + X^{30} + X^{27} + X^{26} + X^{25} + X^{23} + X^{22} + X^{21} + X^{20} + X^{19} + X^{18} + X^{17} + X^{13} + X^6 + X^5 + X^4 + 1$$

---

## 2. Теоретическая модель

Математическое ожидание издержек на одно изделие при доле контроля $P$:
$$E(P) = P \cdot B + P \cdot A \cdot C + (1 - P) \cdot A \cdot D$$

Преобразуем выражение:
$$E(P) = A \cdot D + P \cdot [B + A \cdot (C - D)]$$

Подстановка параметров варианта:
$$E(P) = 0.15 \cdot 125 + P \cdot [7 + 0.15 \cdot (50 - 125)] = 18.75 - 4.25 \cdot P$$

Так как производная $E'(P) = -4.25 < 0$, функция монотонно убывает на всём отрезке $P \in [0, 1]$.  
**Теоретический оптимум:** $P = 100\%$ (сплошной входной контроль всех изделий). Метод Монте-Карло подтверждает этот результат статистически.

## 3. Архитектура проекта и принципы ООП

Проект спроектирован по принципам объектно-ориентированного программирования и SOLID с четким разделением слоев данных, математических расчетов, генерации случайных чисел и графического интерфейса:

* **`src/models.py` (Слой данных / DTO):**  
  Содержит иммутабельные структуры данных на базе `@dataclass(frozen=True)`:
  * `VariantConfig` — инкапсулирует неизменяемые параметры предметной области Варианта 6 ($A = 15\%$, $B = 7$, $C = 50$, $D = 125$, $N = 10\,000$), защищая их от случайной модификации;
  * `SimulationRow` — объект строки таблицы с результатами моделирования (процент контроля, затраты Монте-Карло, теория, погрешность $\vert{}Δ\vert{}$ и флаг `is_optimal`).

* **`src/lfsr.py` (Генератор ПСЧ):**  
  * `IRandomGenerator` (Interface / ABC) — абстрактный интерфейс, реализующий принцип инверсии зависимостей (*Dependency Inversion*). Описывает единый контракт `next_double()`, позволяя подключать любой другой источник случайных чисел без правки бизнес-логики.
  * `LFSR32Generator` (Single Responsibility) — 32-битный регистр сдвига с линейной обратной связью по полиному №15 ($X^{32} + X^{30} + \dots + X^4 + 1$). Побитовая маска отводов формируется по степеням полинома. Для полного устранения автокорреляции между соседними вызовами $R_1$ и $R_2$ метод `next_uint32()` совершает **32 полных такта сдвига** (`clock_bit()`), после чего нормализует значение делением на $2^{32}$ в диапазон $[0.0, 1.0)$.

* **`src/optimizer.py` (Математическое ядро / Сервис):**  
  * `MonteCarloOptimizer` — изолированный класс бизнес-логики. Проводит вычислительный эксперимент с шагом процента контроля (по умолчанию 5%), разыгрывая независимые величины $R_1$ (направление на проверку) и $R_2$ (наличие брака) для $10\,000$ деталей. Считает аналитическое математическое ожидание затрат, отклонение $\vert{}Δ\vert{}$ и определяет строку с глобальным минимумом расходов (`is_optimal = True`).

* **`src/app.py` (Графический интерфейс / Presentation Layer):**  
  * `MonteCarloApp` — класс главного окна на базе фреймворка `CustomTkinter`. 
  * Реализует форму для ввода и изменения параметров $A, B, C, D, N$.
  * Запускает вычисления метода Монте-Карло в отдельном потоке (`threading.Thread`), сохраняя отзывчивость интерфейса при $210\,000$ итерациях.
  * Синхронизирует передачу результатов в GUI через `self.after()`, заполняет прокручиваемую таблицу `CTkScrollableFrame`, подсвечивает зеленым цветом найденный оптимум и формирует итоговое заключение для ЛПР с расчетом чистой экономии.

* **`main.py` (Точка входа):**  
  Инициализирует экземпляр `MonteCarloApp` и запускает цикл обработки событий `mainloop()`.

## 4. Установка и запуск

### Требования
* Python 3.9+
* Менеджер пакетов `pip`

### Шаги запуска

1. Клонировать репозиторий:
```bash
git clone [https://github.com/](https://github.com/)<ваш-аккаунт>/monte_carlo_decision_making.git
cd monte_carlo_decision_making
```

2. Создать и активировать виртуальное окружение:
```bash
# Windows
python -m venv venv
venv\Scripts\activate

# Linux / macOS
python3 -m venv venv
source venv/bin/activate
```

3. Установить зависимости:
```bash
pip install -r requirements.txt
```

4. Запустить приложение:
```bash
python main.py
```
