# Поддержка принятия решений на основе метода Монте-Карло (C# / .NET 8)

Лабораторная работа №5 по дисциплине «Базы знаний и поддержка принятия решений».  
Проект реализует имитационную модель оптимизации затрат на входной контроль комплектующих изделий (резисторов) с использованием псевдослучайных чисел на базе регистра сдвига с линейной обратной связью (LFSR).

---

## 1. Постановка задачи (Вариант 6)

На производство поступает партия резисторов ($N = 10\,000$ шт.).  
Требуется определить долю деталей ($P \in [0, 1]$ с шагом 5%), подвергаемых предварительному входному контролю, при которой общие затраты предприятия будут минимальны[cite: 1].

### Исходные параметры:
* **$A$ (доля брака):** $15\%$ ($p_{\text{def}} = 0.15$)
* **$B$ (стоимость входного контроля одного резистора):** $7$ руб.
* **$C$ (стоимость подгонки при выявлении брака на контроле):** $50$ руб.
* **$D$ (стоимость замены бракованного резистора в готовом блоке):** $125$ руб.
* **Генератор ПСЧ:** Регистр сдвига с линейной обратной связью (LFSR), **полином №15** (степень 32).

---

## 2. Математическая модель

Математическое ожидание суммарных затрат $E(P)$ на один резистор:
$$E(P) = P \cdot B + P \cdot A \cdot C + (1 - P) \cdot A \cdot D$$

Преобразуем формулу:
$$E(P) = A \cdot D + P \cdot [B + A \cdot (C - D)]$$

Подставляем числовые значения:
$$E(P) = 0.15 \cdot 125 + P \cdot [7 + 0.15 \cdot (50 - 125)] = 18.75 - 4.25 \cdot P$$

Поскольку коэффициент при $P$ отрицателен ($-4.25 < 0$), функция $E(P)$ монотонно убывает при увеличении доли проверки $P$.  
**Теоретический оптимум:** $P = 100\%$ (сплошной входной контроль всех изделий). Метод Монте-Карло эмпирически верифицирует данную аналитическую оценку.

## 3. Архитектура решения


* **`IRandomGenerator`**  
  Интерфейс генератор псевдослучайных чисел. Позволяет заменять LFSR на любой другой генератор (например, стандартный `System.Random` или криптографический `RandomNumberGenerator`) без изменения логики симулятора.
* **`LFSR32Generator`**  
  Реализует генератор LFSR степени 32 по полиному №15:
  $$X^{32} + X^{30} + X^{27} + X^{26} + X^{25} + X^{23} + X^{22} + X^{21} + X^{20} + X^{19} + X^{18} + X^{17} + X^{13} + X^6 + X^5 + X^4 + 1$$
  Для эффективного вычисления бита обратной связи используется аппаратная инструкция подсчёта битов `BitOperations.PopCount`.
* **`VariantConfig` & `SimulationResult`**  
  Неизменяемые типы данных, предотвращающие случайную мутацию конфигурации и результатов в ходе расчётов.
* **`MonteCarloOptimizer`**  
  Инкапсулирует статистический розыгрыш двух независимых случайных событий ($R_1$ — отправка на контроль, $R_2$ — наличие скрытого дефекта) и расчёт теоретического математического ожидания.
* **`DecisionSupportReporter`**  
  Изолирует форматирование вывода и предоставление рекомендаций от вычислительного ядра.
